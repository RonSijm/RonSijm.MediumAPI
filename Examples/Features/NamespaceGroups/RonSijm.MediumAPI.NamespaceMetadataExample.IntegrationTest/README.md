# Namespace metadata and generated-prefix checks

The existing 17 cases retain their native namespace metadata, documentation,
conditional exposure and HTTP checks. DeclarativeNamespaceTests adds 12 cases
per framework using a separately selected scenario in the runnable example.

The real NamespaceRouteGroupAttribute keeps its exact readonly prefix and
class-only, noninherited usage, accepts empty strings and rejects null. Partial
definitions generate the native MapGroup call; parameterized and empty prefixes
compose through normal namespace ownership. Independent native references retain
route contracts, API Explorer, typed payloads, actual response bytes/headers,
ordered tags/custom metadata, named links and constraints. The prefix declaration
does not appear in endpoint metadata or activate request targets during inspection.

Tests preserve class convention/host callback/nested group order, unnamed alias
boundaries, fresh metadata for independent mounts and current per-operation
availability. Disabled parents skip child conditions, conventions and callbacks;
later enabled mapping evaluates conditions again. Direct child mounts use the
explicit host prefix and selected child's own prefix. Both default and declarative
public Program.Build branches are exercised.

The native reference forwards original delegates through an opaque native
MapMethods helper, avoiding the SDK analyzer's cross-assembly method-group issue
without suppressing analyzers or wrapping handlers. The example adds no routing,
validation or middleware engine. A separate generator suite covers real emitted
compilation/native method symbols, exact constant strings, invalid owner/configuration
shapes and conservative prefix analysis before/after generation.

The expected example total is 29 cases on each existing net8.0/net10.0 target.
See [the runnable example](../RonSijm.MediumAPI.NamespaceMetadataExample/README.md),
[prefix contract](../../../../Docs/declarative-namespace-prefixes.md) and
[verification record](../../../../Docs/testing-and-development.md#current-verification-record)
for executed outcomes and scope. These synthetic checks do not certify another
application's full host, authorization, deployed routes or OpenAPI provider.

## Tag-default migration checks

`TagDefaultMigrationTests` adds ten cases per framework through a separate
five-route public scenario. The previous 29 cases and their source assertions
remain unchanged; the complete project now has 39 cases on each target.

Independent references retain the earlier method tags and equivalent native
group tags. Strict full route snapshots, full API Explorer descriptions and
the provider's selected tag metadata agree with the migrated scenario. Actual
HTTP bodies, status/media, endpoint names and explicit unnamed alias tags agree
too. Two uniform handlers inherit one namespace default; different method and
child tags keep their native priority.

Raw ordered tag history deliberately changes for child and method overrides:
an earlier parent default now exists even when a later declaration wins. Tests
observe that change separately and compare the complete ordered history with
the equivalent native group reference. No normalization changes the comparator.
Manual aliases retain their own explicit tags outside namespace ownership;
repeated typed mounts and separate hosts retain fresh metadata collections.
The runnable opt-in entry point and unchanged default route selection are
exercised directly.

These checks use the existing native API Explorer provider and packages. They
do not generate an OpenAPI document or establish another host's provider output.
See [namespace tag migrations](../../../../Docs/namespace-tag-defaults.md) and the
[verification record](../../../../Docs/testing-and-development.md#current-verification-record).

## Declarative endpoint-pattern compatibility checks

EndpointPatternTests adds 16 cases to the existing 39 on each existing .NET 8/.NET 10
target. It uses the runnable example's Sample:EndpointPatterns selection and leaves
the original default and earlier scenarios unchanged. No package or project change
is required.

The actual runtime attribute is checked for exact/empty read-only values, null
rejection, declared class-only single usage and its constructor's route annotation.
Generated properties are public read-only strings with StringSyntax("Route"). The
original HandleAsync MethodInfo, route aliases/types and services remain native.

Three independent arrangements expose the same static GET, constrained GET and
constrained POST: declarative-pattern MediumAPI, old explicit-property MediumAPI
and native original-Delegate MapMethods mappings. The native filter is implemented
independently; its 400 metadata uses native ProducesResponseTypeMetadata, and native
handlers assign their no-store headers on entry. The explicit-property fixture's
namespace is disabled for bulk discovery and mapped deliberately by the checks.

Complete route/API Explorer comparisons retain established names, tags, synthetic
Authorize policy metadata, typed response contracts and all required long route
parameters. HTTP cases compare exact payload bytes/media/status and headers,
including both long limits and the POST handler's explicit 404. Filter rejection
stays before the handler-owned header; invalid native constraints reach neither
filter nor handler. Native names/links, explicit alias pattern/name overrides and
the public opt-in/default branches have real request coverage.

The PatternRead policy deliberately permits sample requests; these checks do not
establish real identity/security behavior. This pair has API Explorer, with no
OpenAPI document provider, database or consuming application's services. See the
[runnable example](../RonSijm.MediumAPI.NamespaceMetadataExample/README.md),
[pattern guide](../../../../Docs/endpoint-patterns.md) and
[verification record](../../../../Docs/testing-and-development.md#current-verification-record)
for exact feature boundaries and executed outcomes.
