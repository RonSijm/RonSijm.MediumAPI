# OpenAPI migration example

This dual .NET 8/.NET 10 example registers equivalent endpoints in two independent
ways: ordinary Minimal API builders and MediumAPI endpoint classes. Both use the
same synthetic contracts, service and provider configuration. The companion tests
compare the complete, unmodified JSON generated by the real Swashbuckle provider,
as well as route/API Explorer snapshots and actual HTTP behavior.

| Method/path | Contract |
| --- | --- |
| `GET /api/products/{productId:long}` | Aliased route argument, nullable search/header inputs, query default `take=10`, typed 200/404 and default name `GetProduct` |
| `POST /api/products` | Required JSON contract, typed 201/400, Location header and default name `CreateProduct` |
| `GET /compat/products/{productId:long}` | Unnamed alias retaining the GET contract without inheriting a namespace prefix |
| `GET /api/internal-status` | Reachable typed response deliberately excluded from API Explorer/OpenAPI |

Product 17 returns a fixed synthetic catalog item. Successful creates return
identity 23 and copy the supplied fields; nothing is persisted. Blank names return
`{"code":"name-required"}`. The catalog records dispatch counts and the last GET
arguments so inspection can be distinguished from requests. Search and
`X-Sample-Trace` inputs do not alter the response payload. Both GET registrations
retain `Cache-Control: no-store` and `Pragma: no-cache`; the native handler writes
them directly and the class handler declares the equivalent response policy.

`Program.Build(MappingStyle.Native)` selects the Minimal API implementation;
`Program.Build()` selects MediumAPI. The standalone entry point accepts `--native`
to select the native branch. After startup, `Main` explicitly captures
`Program.GetOpenApiJson(app.Services)` into a debugger local. Nothing exposes,
logs, saves or asserts a document automatically. Callers choose when to capture
and compare their documents.

The example alone references
[Swashbuckle.AspNetCore.SwaggerGen 10.2.3](https://www.nuget.org/packages/Swashbuckle.AspNetCore.SwaggerGen/10.2.3),
which contains .NET 8/.NET 10 provider assets. This adds no provider dependency to
the core runtime. The configured serializer contract resolver uses the same HTTP
JSON options as the handlers. No package-version or provider output normalization
is applied. The default provider operation IDs are retained: primary names are
explicit on native builders and derived from class names in MediumAPI, while the
alias has no name or reconstructed operation ID.

The documents include real request/response schemas and provider-described query
defaults. Structural equality covers this fixture and provider version; it is
not complete schema-semantic, serializer, security or cross-version equivalence.
The fixture does not add authentication or an authorization-policy interpreter.
Compare hosts on the same target first and review provider-version differences
explicitly. See [contract snapshots](../../../../Docs/contract-snapshots.md),
[API Explorer snapshots](../../../../Docs/api-description-snapshots.md) and the
[verification record](../../../../Docs/testing-and-development.md) for boundaries and
executed results.
